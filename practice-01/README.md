Результат после исправления:


Таблица
| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления | Исправление | Результат после исправления |
|---|---|---|---|---|---|---|
| Обработка количества задач | `console.log("Выполнено:", completedTotal)` выводил `"32"` вместо `5`. Строка `remainingTasks = plannedText - completedTotal` давала `-24` вместо `3`. | Оператор `+` со строковыми операндами выполняет конкатенацию, а не сложение. `completedText` и `additionalText` имели тип `string` (`"3"` и `"2"`), поэтому `"3" + "2"` склеилось в `"32"`. Дальше `"8" - "32"` привело обе стороны к числам и дало `-24`. | Явное преобразование строк в числа: `Number(completedText) + Number(additionalText)`. Аналогично для `remainingTasks` — через `Number(plannedText)`. | `Выполнено: 5`, `Осталось: 3`. Значения совпадают с ожидаемыми, типы — `number`. | Унарный плюс `+completedText + +additionalText` как альтернатива `Number()`. | `Выполнено: 5`, `Осталось: 3`. Результат идентичен, запись короче, но менее наглядна. |
| Граница цикла | `controlSum` после цикла равнялась `6` (`1 + 2 + 3`), а ожидалось `10`. Последняя итерация с `taskNumber = 4` не выполнялась. | Условие `taskNumber < 4` останавливает цикл, когда `taskNumber` становится равным `4`, то есть само значение `4` в тело цикла не попадает. Нужна была нестрогая граница. | Заменил условие на `taskNumber <= 4`, чтобы включить значение `4` в диапазон итераций. | `Контрольная сумма: 10` (`1 + 2 + 3 + 4`). Цикл выполнился 4 раза вместо 3. | Изменил стартовое значение на `taskNumber = 0` при условии `taskNumber < 4` — тогда сумма `0 + 1 + 2 + 3 = 6`, это неверно. | Оставил вариант с `<= 4`: он даёт правильные `10` и читается естественнее. |
