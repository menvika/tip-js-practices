## 4. Модель данных и функции

**Поля задачи:**

{
  id: number,          - положительное целое число, уникальное в пределах набора
  title: string,       - непустая строка, до 100 символов после trim
  completed: boolean,  - true или false
  priority: string     - "low", "medium" (по умолчанию) или "high"
}

**Правила валидации:**

Валидация выполняется в `createTask`. Остальные операции переиспользуют её правила: `addTask` — через прямой вызов `createTask, renameTask`— через `createTask` на копии задачи с новым названием, чтобы не дублировать проверки.

**Назначение файлов:**
- `src/data.js` — данные: `demoTasks, variantNumber, variantTasks`. Только константы, никакой логики.
- `src/task-service.js` — прикладная логика: девять функций, валидация, создание новых массивов. Не мутирует входные данные.
- `src/main.js` — сценарий: только вызовы функций и вывод в консоль. Заменяет текущее состояние результатом `result.tasks` при успехе, оставляет прежним при ошибке.
- `checks.js` — 35 проверок на `node:assert/strict`. Не входит в прикладной код.

**Результаты операций**

| Операция | Успех | Ошибка |
|---|---|---|
| `createTask` | `{ ok: true, task: {      id: id,      title: title.trim(),      completed: false,      priority: priority    } }` | `{ ok: false, error: "'тип ошибки'" }` |
| `findTaskById` | найденный объект | — |
| `getPendingTasks` | новый массив `completed === false` | — |
| `getTaskTitles` | новый массив строк | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask` | `{ ok: true, tasks: [...tasks, created.task] }` | `{ ok: false, error: 'Задача с id=${id} уже существует' }` |
| `setTaskCompleted` | `{ ok: true, tasks: updatedTasks }` | `{ ok: false, error: 'Задача с id=${id} не найдена' }` |
| `renameTask` | `{ ok: true, tasks: updatedTasks }` | `{ ok: false, error: 'Задача с id=${id} не найдена' }` |
| `removeTask` | `{ ok: true, tasks: updatedTasks }` | `{ ok: false, error: 'Задача с id=${id} не найдена' }` |


**Почему id не равен индексу:** потому что id — стабильный признак задачи, он не меняется при добавлении, удалении и переупорядочивании  
**Почему getTaskStats возвращает число, а не строку с процентом:** потому что функция вычисляет значение по формуле completed / total * 100 — это число 

**Какие объекты копируются при изменении задачи:** массив и изменяемый объект.

## 9. Вывод

В ПР1 каждая программа была отдельной и работала с простыми переменными. В ПР2 появился общий модуль функций и единая модель задачи. Каждая функция возвращает либо результат `{ ok: true, tasks: [...] }` или `{ ok: false, error: "..." }`, либо новое значение — и при этом не меняет входные данные.

Это необходимо для сценария: если `result.ok === true`, текущий массив задач заменяется на `result.tasks`; если `false` — остаётся прежним. 

Что данные не меняются, проверено двумя способами:
1. В конце `main.js` выводятся id из `demoTasks` и `variantTasks` — оба массива остались в исходном составе и порядке
2. Также в `checks.js` есть отдельный сценарий № 33, который проверяет, что ни одна из девяти функций не портит входные объекты
